# ThermPrint project decisions

The user requested a browser printing app hosted on GitHub Pages, with `rawsock/thermprint` as its upstream. Use static HTML/CSS/JavaScript for the browser runtime; retain Python for the existing diagnostics. See README.md for usage and development commands.

## Printer

The TEDi SWS-PT1 supports custom BLE printing through FFE6/FFE1/FFE2. On 2026-11-08 the Python diagnostic completed authentication and a 120-packet calibration job, including transfer and footer acknowledgements; the user confirmed a good physical print. The calibration width is 384 dots. Application authentication derives its response from the printer-reported MAC rather than a fixed device address.

The browser port preserves 100-byte application packets and conservative 40 ms pacing. It honors printer holds and one-based retry requests, and requires the matching completion acknowledgement. Automatic replay after disconnect is excluded because already printed paper cannot be recalled. The user subsequently confirmed that browser printing works.

Reuse the selected BluetoothDevice for reconnects and restore site-granted devices with feature-detected getDevices on page load. Prefer the saved opaque device ID; do not choose arbitrarily among multiple grants. Keep an explicit chooser action for switching printers. Tests cover reauthentication, listener cleanup, canceled switching, and revoked permissions. Browser support determines whether permission survives a reload.

Paper-feed compensation defaults to 29 / 25.5 (about 113.7%): the user measured a circular image as 29 mm across and 25.5 mm along the paper. Resize continuous gray tones before dithering so the final print grid has no duplicated dot rows; preserve nearest-neighbor binary correction for non-dithered text and QR codes. Keep the preview and PNG at intended proportions, with their own quantization at that resolution. Store the adjustable correction locally and enforce the 1536-row limit after correction. The later QR distortion report has no new measurement; retain the measured default and expose neutral 100% and measured-reset actions. Tests confirm square QR artwork and a single correction. Center binary resampling within each output row: the previous floor sampling could omit the last source row below 100%. Packet round-trip tests retain edge rows at 80–140% including odd heights; the user's intermittent missing-row incident has not been reproduced on hardware.

Keep print adjustments adjacent to the preview, with independent scrolling and fixed control positions: disable unavailable options rather than hiding or collapsing them. User feedback requested less blank paper: reduce added vertical space from 96 rows to 4 leading + 16 trailing rows by default (about 2.5 mm total before compensation); independently allow 0–64 rows at either end and remove the old 96-row minimum job height. Preserve horizontal margins and QR quiet zones. Source whitespace and any printer-generated feed are distinct from added margins. Scaling images to 10–100% of their fitted size keeps them horizontally centered and reduces paper height with content; spacing remains constant.

## Image quality

Native grayscale is an optional four-tone mode for compatible firmware; binary remains the default and QR codes always use it. Negotiate support before raster transfer, preserve a terminal guard packet, and wait for rendered-row and final-feed completion. Fine row pitch doubles encoded height while preserving preview and paper proportions. Stucki and Atkinson error diffusion support any integer 2?256 tone count, with the initial wire modes exposing 2 and 4. The common four-tone curve remains approximate; actual-image acceptance is pending.

Use serpentine Stucki diffusion for photos, with small deterministic threshold variation to break repeating patterns. Offer Atkinson as a crisper illustration option. Adjust input tones for ink balance, with contrast that preserves white/black endpoints and optional mild sharpening. Moving the diffusion threshold alone conserved nearly the same ink coverage and made the old slider ineffective.

Default to a softened paper preview, using mild optical blending and dark-gray ink for screen display only. Retain an exact-dot preview option and binary PNG export. This addresses the user's report that screen dots looked harsher than paper without modifying the working print raster.

Against the pre-change raster code in commit 3faba7b, a 384 × 256 constant-gray patch had 63 repeated adjacent rows after feed correction; the new print raster had zero. At ink settings 80/160/220, coverage changed from approximately 49.7/49.9/50.0% to 29.0/49.8/68.7% with neutral contrast. Regression tests cover tone density, clean white feed, corrected-size limits, and QR decoding. Sample photograph and gradient comparisons were visually inspected in software; physical print quality still needs confirmation.

## Delivery

Serve only the `site/` directory through GitHub Pages. Use relative asset URLs for the repository path. Text, imported images, drawings, and QR data stay in browser memory. The QR encoder is vendored from qrcode-generator 2.0.4 (MIT); canvas rendering and QR decoding packages are development-only dependencies.

Offer English/Polish and System/Light/Dark selectors in the page header, saved locally with graceful fallback when storage is blocked. Translate static UI and dynamic messages without changing editable content or graphics metadata. Theme changes preserve actual paper and artwork colors. Preference tests cover restoration, live switching, and blocked storage.

Use Iconify as the default graphics source, as requested after the user found the Commons pixel filter too slow. The removed filter took about 7 seconds for 12 “cat” drawings; Iconify returned 128 unfiltered “cat” icons in about 0.2 seconds during research on 2026-11-08. Filter monochrome collections through metadata, not image inspection. Show 48 items at a time; request 96 names initially and remaining matches only when needed, buffering extra results. Fetch a larger SVG only on selection and rasterize it in an image context, never as inline page markup. Keep Wikimedia Commons as an optional source for photos and other images. Display creator/license/source metadata and explain empty results without silently changing the query. All library requests go directly from the browser, without keys or a backend.

Openclipart had 27 “funny cat” results, but its image endpoints returned duplicate Access-Control-Allow-Origin values; direct browser import would need a proxy. Iconify returned no matches for that phrase, so suggest short subjects. Live app integration retrieved 87 monochrome “cat” icons across two metadata requests in about 0.23 seconds, decoded the selected SVG, and rendered printable pixels. Both Iconify's search and SVG endpoints returned valid CORS headers.

The user created the `thermprint` organization and has active admin membership, verified through GitHub's API. Publish the branded site at `https://thermprint.github.io/` from `thermprint/thermprint.github.io`. Keep `rawsock/thermprint` as the development upstream and the original project site available. This workspace has a `pages` remote and two `origin` push URLs so ordinary pushes update both repositories; fetching and branch tracking stay on `rawsock/thermprint`. Changes made outside this workspace also need to reach both repositories. No personal account homepage is used.
